# 같은 과제로 본 에이전트 비교 (2026-10)

메일함으로 연결한 에이전트들에게 **같은 과제를 같은 지시문으로** 맡겨 결과를 비교한 기록이다. 어떤 일을 누구에게 보낼지 정하는 데 썼다. 과제마다 한 번씩만 돌렸으므로 벤치마크가 아니라 사례 기록으로 읽어야 한다.

## 조건

| 항목 | 내용 |
|---|---|
| Gemini | Antigravity CLI(`agy`) 비대화형 실행, `gemini-4-argon-high`, 권한 자동 승인 |
| Codex | Codex CLI `codex exec`, `gpt-6-astra`, 추론 high. Windows에서는 `workspace-write` 샌드박스가 명령을 실행하지 못해, 일회용 폴더에서 샌드박스 우회 모드로 실행(Gemini와 같은 조건) |
| 로컬 모델 | Ollama `qwen3-coder:30b`, `gpt-oss:20b`. 도구 없이 한 번에 답하게 함(문맥 32K) |
| 요금제 | Gemini·Codex 모두 기본 유료 요금제 |
| 진행 | 각 에이전트는 자기 복사본 폴더 또는 자기 git worktree에서 작업. 같은 지시문, 한 번 실행. 채점은 Claude Code가 정답표와 독립 검토로 함 |

## 과제와 결과

### 1. 심어 둔 결함 찾기 (검증)

작은 파이썬 데이터 처리·시뮬레이션 모듈(파일 7개 안팎)의 복사본에 결함 7개를 일부러 넣고, 규칙 문서와 대조해 찾게 했다. 넣은 결함은 시간 구간 경계 오류 2개, 백분위 계산에 당일 값이 섞이는 미래 정보 유입, 보유 기간 비교 연산자(`>` 대 `>=`), 매도 수수료 부호, 판정 규칙의 순서, 자료 마감일 하루 초과다.

| 에이전트 | 찾은 결함 | 그 밖의 지적 | 걸린 시간 |
|---|---|---|---|
| Gemini | 7/7 (1개는 "불확실"로 표시) | 오탐 0, 넣지 않은 실제 결함 2건 추가 | 약 5분 |
| Codex | 7/7 | 규칙 문서와 어긋나는 구현 누락 등 추가 지적 12건(정답표 밖이라 채점하지 않음), "불확실" 5건 별도 표시 | 약 4분 |
| qwen3-coder 30B | 1/7 | 확신에 찬 틀린 주장 약 13건 | — |
| gpt-oss 20B | 답 없음 | 추론이 출력 한도를 다 써 버림 | — |

### 2. 설계 검토 (사전 등록 초안)

실행 전에 규칙을 고정해 두는 정량 연구 초안(약 11 KB)을 검토하게 했다. 채점 기준은 앞선 검토에서 나온 "등록 전 고쳐야 할" 항목 10개다.

| 에이전트 | 기준 항목 | 비고 |
|---|---|---|
| Codex | 10/10 | HIGH 15건, MEDIUM 포함 상세 수정안 |
| Gemini | 9 + 부분 1 | 기준에 없는 타당한 지적 추가, 약 8분, 19항목 |
| gpt-oss 20B | 2 + 부분 3 | 미래 정보 유입에 대한 틀린 주장 1건 |
| qwen3-coder 30B | 1 + 부분 3 | 문서에 없는 사실을 지어냄 |

### 3. 개발 (작은 기능)

기존 코드베이스 관례를 따라 보고서 명령 하나를 만드는 과제다. 새 파일 4개(모듈, CLI, 실행 스크립트, 테스트)이고, 테스트를 먼저 쓰게 했다.

| 에이전트 | 결과 | 걸린 시간 |
|---|---|---|
| Codex | 테스트 19개. 독립 검토에서 HIGH 없음. 스스로 리뷰를 돌려 MEDIUM 1건을 고침. 채점자가 이쪽을 머지 권고 | 작업 약 10분(사용 한도로 끊겨 `codex exec resume`으로 이어서 실행) |
| Gemini | 테스트 8개. 린트·타입·테스트는 첫 시도에 통과했지만, 독립 검토에서 HIGH 1건(프로세스를 재시작하면 처음부터 다시 세는 번호를 키로 써서 재시작 뒤 조회가 깨짐). 첫 번째 Claude 검토도 이것을 놓침 | 약 17분 |

## 운영에서 드러난 점

- **Codex의 가장 큰 제약은 사용 한도다.** 기본 요금제에서 하루에 세 번 한도에 걸렸다. 걸리면 해제 시각까지 기다리거나 `resume`으로 이어야 한다.
- **Gemini는 같은 기간 한도 문제가 없었다.** 검증·재계산처럼 반복되는 일을 맡기기 좋다.
- **로컬 모델(30B 이하)은 검증과 설계 검토에 쓸 수 없었다.** 틀린 주장을 확신을 갖고 하거나 답을 내지 못했다. 로그 요약 같은 잡무에만 후보로 남았다가, 그것도 쓸 일이 적어 꺼 두었다.
- **개발 결과물은 만든 모델과 다른 쪽이 한 번 검토해야 한다.** 테스트가 모두 통과해도, 재시작이나 경계 조건 같은 숨은 결함은 독립 검토에서야 나왔다.
- **Windows에서 Codex 샌드박스**(`workspace-write`)는 명령을 실행하지 못한다. 비교 작업은 일회용 폴더에서 우회 모드로만 돌렸다.

## 이 결과로 정한 분배

| 일 | 담당 |
|---|---|
| 검증, 재계산, 반복 점검, 개발 초안 | Gemini (기본) |
| 중요한 설계 검토(사전 등록 초안, 방법론 비판) | Codex |
| 개발 결과물의 머지 전 검토 | 만든 쪽과 다른 에이전트가 한 번 |
| 검증·설계 검토 | 로컬 모델에 맡기지 않음 |

같은 일을 두 에이전트에 중복으로 맡기지 않는다. 한쪽이 한도에 걸리면 다음 독립 작업은 다른 쪽으로 보낸다.

## 한계

- 과제마다 한 번씩만 실행했다. 모델 출력은 실행마다 달라질 수 있다.
- 과제 3개는 모두 한 저장소의 파이썬 코드와 문서에서 나왔다. 다른 언어나 큰 변경에서는 결과가 다를 수 있다.
- 모델 이름과 요금제는 2026년 10월 기준이다.
